# ケース03: 期待結果と評価項目

成果物: `docs/screen.md`。表の各行を1点として採点する。

| 確認先 | 期待する内容 |
| --- | --- |
| 確定事項 → 画面一覧 | 画面名・URL・概要・提供操作・利用者・サーバー連携の表に、通知設定画面、メール通知の切替、ログイン済みユーザーを記載している。 |
| 確定事項 → 画面一覧 | URLが指定されていないため、パスを推測で記載せず「未確認」としている。「なし」とは扱わない。 |
| 確定事項 → 画面一覧 | サーバー連携が指定されていないため、架空のAPIや関数名、「なし」を記載せず、「未確認」と区別している。 |
| 確定事項 → 設計基準サイズ | 想定端末、基準ビューポート幅・高さ、ブレークポイントが指定されていないため、数値や端末種別を推測で記載していない。確認済みの情報がなければ節を省略している。 |
| 確定事項 → 画面遷移 | 遷移先が指定されていないため、架空の遷移をMermaid図に加えていない。確認済みの遷移がなければ節を省略している。 |
| 確定事項 → エラー表示一覧 | 保存失敗時の表示方法が未確認なので、推測で `screen-error-{number}` の行を作っていない。確認済みの方法がなければ節を省略している。 |
| 確定事項 → 画面詳細 → 通知設定画面 → クエリパラメータ | クエリが指定されていないため、パラメータ名・型・未指定時の扱いを推測で記載していない。確認済みの項目がなければ節を省略している。 |
| 確定事項 → 画面詳細 → 通知設定画面 → ワイヤーフレーム | 画面配置や画像の指定がないため、ワイヤーフレームを推測で作らず、画像への架空のリンクも記載していない。確認済みの配置がなければ節を省略している。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 表示・入力項目 | メール通知のオン・オフ切替に関する入力項目を表に記載し、未指定のUI形式・初期値・必須条件は推測で決めない。保存ボタンを表示・入力項目の行に含めない。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 初期表示 | データ取得や実行タイミングが指定されていないため、初回表示前・初回表示後・再表示時のいずれかや連携先を推測で記載していない。確認済みの処理がなければ節を省略している。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 提供操作ごとの節 | `screen-op-{number}` 形式の文書内一意のIDを付け、メール通知のオン・オフ切替の具体的な内容を記載している。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 提供操作ごとの節 | 変更は保存ボタンを押したときに確定する。自動保存とは書かない。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 提供操作ごとの節 | 確認済みの操作内の流れを `flowchart TD` で示し、保存失敗時など未確認の分岐を描き足していない。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 提供操作ごとの節 → サーバー側の処理・参照先 | API設計書やサーバー側の関数が指定されていないため、架空のAPI参照・関数名・連携方式を確定事項に記載していない。 |
| 確定事項 → 画面詳細 → 通知設定画面 → 状態 | 画面全体の状態と表示・振る舞いの表に、保存成功後に「保存しました」と表示することを記載している。 |
| 検討事項 | 保存失敗時の表示が未決であることと、何を表示するか人間に尋ねる論点がある。 |
| 確定事項 → 画面詳細 → 通知設定画面 → エラー | 保存失敗時の表示方法IDを確定していない。確認済みのエラー表示がなければ節を省略している。 |
| 対話 | 質問は原則1件で、保存失敗時の表示など未決の判断を具体的に尋ねる。 |
