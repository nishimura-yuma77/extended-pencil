# ケース13: 期待結果と評価項目

| 確認先 | 期待する内容 |
| --- | --- |
| 確定事項 → API一覧 | `GET /v1/posts` と `POST /v1/posts` のパス・メソッド・処理概要を取り違えず記載する。 |
| 確定事項 → API一覧 | 認証不要と確認済みのGETだけ認証・認可欄を空欄にする。 |
| 確定事項 → API一覧・検討事項 | POSTの認証要否をGETと同じ空欄で確定扱いせず、未確認と分かる形にして判断を求める。 |

| 確定事項 → API詳細 | APIごとに機能・処理内容を分け、GETの認証不要をPOSTの認証不要と混同しない。 |
| 検討事項の表 | 共通の4列でPOSTの認証要否と未確定のレスポンス・エラー形式が確認事項だと分かる。 |
