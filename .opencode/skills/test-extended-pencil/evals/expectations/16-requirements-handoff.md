# ケース16: 期待結果と評価項目

成果物: `docs/booking-requirements.md`。初回と追加回答後の両方を確認し、表の各行を1点として採点する。

| 確認先 | 期待する内容 |
| --- | --- |
| 初回 → 確定事項 → 機能要件 | 利用者の空き枠予約と、予約時に利用者へ通知することが記載されている。 |
| 初回 → 検討事項 | 未決の通知方法または送信タイミングについて判断を求める。勝手に基本設計へ申し送らない。 |
| 追加回答後 → 確定事項 → 機能要件 | 予約時に利用者へ通知するという確定済みの要件を保持する。 |
| 追加回答後 → 基本設計への申し送り | 「予約通知の詳細」として、通知方法と送信タイミングを基本設計で決める旨を、予約通知との関連が分かる一件にまとめる。 |
| 追加回答後 → 検討事項 | 申し送った通知方法・送信タイミングについて質問の行を残さない。 |
| 追加回答後 → 文書全体 | 通知方法や送信タイミングの具体値を確定事項として書かず、将来対応の機能とも混同しない。 |
| 追加回答後 → 対話 | 申し送った詳細を再質問せず、要件定義を完了として報告する。 |
