# ケース01: 期待結果と評価項目

成果物: `docs/requirements.md`。表の各行を1点として採点する。「確認先」は見出しと表の列を指し、同じ意味なら表現は問わない。

| 確認先 | 期待する内容 |
| --- | --- |
| 確定事項 → 機能要件の表 | 機能名＝空き枠の閲覧、概要＝お客さんが空き枠を見られる、利用者・対象＝お客さん。 |
| 確定事項 → 機能要件の表 | 機能名＝予約、概要＝お客さんが予約できる、利用者・対象＝お客さん。 |
| 確定事項 → 機能要件の表 | 機能名＝予約の承認、概要＝店舗担当者が予約を承認できる、利用者・対象＝店舗担当者。 |
| 確定事項 → 将来対応の表 | 機能名＝決済、概要＝初版では扱わない。 |
| 確定事項 → 将来対応の表 | 将来の実施決定や時期を断定していない。 |
| 確定事項 → 機能要件・将来対応の表 | 決済を初版の機能要件に混ぜず、表に不要な項目ID列を追加していない。 |
| 検討事項の表 | タイトル＝キャンセルの締切、内容＝締切は未決、関連項目＝予約、判断してほしいこと＝期限を尋ねる質問。 |
| 検討事項の表 | 共通の「タイトル・内容・関連項目・判断してほしいこと」の列で、未決事項を行として表現している。 |
| 確定事項全体 | キャンセルの締切日・時刻を確定値として記載していない。 |
| 対話 | 次に尋ねる質問は原則1件で、キャンセルの締切など未決の判断を具体的に尋ねる。 |
