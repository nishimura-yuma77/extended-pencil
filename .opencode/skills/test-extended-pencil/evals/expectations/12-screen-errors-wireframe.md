# ケース12: 期待結果と評価項目

成果物: `docs/login-screen.md`。表の各行を1点として採点する。

| 確認先 | 期待する内容 |
| --- | --- |
| 確定事項 → 画面一覧 | `/login`、ログインと認証コード再送、サーバー連携「未確認」を示す。「なし」とは扱わない。 |
| 確定事項 → ログイン画面 → ワイヤーフレーム | 指定された見出し・入力欄・二つのボタンの上下関係をテキスト図で示し、架空の画像リンクを作らない。 |
| 確定事項 → ログイン画面 → 表示・入力項目 | メールアドレスとパスワードを必須の入力項目として記載し、ボタンを入力項目の行に混ぜない。 |
| 確定事項 → ログイン画面 → 操作 | ログインと再送に異なる文書内一意の `screen-op-{number}` IDを付け、それぞれの節で確認済みの操作を記載する。 |
| 確定事項 → ログイン画面 → 操作 | 確認済みの操作内の流れを操作ごとのMermaid `flowchart TD` で示し、未決の成功時遷移先を描かない。 |
| 確定事項 → エラー表示一覧 | パスワード欄の直下とトーストを別の `screen-error-{number}` IDで定義する。 |
| 確定事項 → ログイン画面 → エラー | パスワード不一致と通信失敗をそれぞれ該当する操作ID・表示方法IDに対応付け、確定した二つの文言をエラー表示一覧の概要または画面エラーの説明に残す。 |
| 確定事項 → 画面遷移 | 成功時の遷移先を推測で作らず、確認済みの画面遷移がなければ節を省略する。 |
| 検討事項の表 | 共通の4列で成功時の遷移先など未決の判断を具体的に質問し、サーバー関数名は作らない。 |
| 対話 | 原則1件で成功時の遷移先など未決の判断を尋ねる。 |
