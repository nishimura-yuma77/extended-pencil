# test-extended-pencil

エージェント共通で利用できるリポジトリ直下の `SKILL.md` とそのテンプレートを評価対象、このリポジトリ専用の `evals/` を評価セットとして扱う。設計文書を作る通常の依頼には使わない。

## 親エージェントの進め方

1. `evals/README.md` と対象ケースの `evals/prompts/` を読み、ケースを選ぶ。指定がなければ全件。生成が終わるまで `evals/expectations/` を読まない。指示文中の引用した依頼だけを、順番にユーザーの発言として渡す。
2. `.opencode/skills/test-extended-pencil/.work/<実行ID>/<ケースID>/` にケースごとの作業ディレクトリを用意する。Taskで文書生成・採点を行える汎用エージェント（利用可能なら `general` 型など。調査専用の `explore` は使わない）を、**ケースごとに新しいセッション**として起動する。初回起動では `task_id` を指定せず、共通の対話履歴や期待結果も渡さない。独立したケースは並行実行してよい。
3. Taskへの依頼には、リポジトリ直下の `SKILL.md`、該当テンプレート、当該ターンの依頼文、ケース専用の作業ディレクトリを明示する。生成中は期待結果と他ケースの指示文を読まないよう伝える。サブエージェントは成果物・質問・実行時の問題をそのディレクトリに保存し、成果物のパスと質問を返す。指示文の `docs/` などの出力先はケースの作業ディレクトリを基準にする。評価対象の `SKILL.md`、テンプレート、評価ケースは変更しない。
4. 複数ターンのケースは、初回の成果物をスナップショットとして、質問を `dialogue.md` に保存してから、**そのケースの `task_id` のみ**を使って追加回答を渡す。回答後の文書と質問も保存する。追加回答を初回のTask依頼に含めたり、別ケースのTaskへ渡したりしない。
5. 最終成果物と対話が保存された後に、親が当該ケースの `evals/expectations/` を読み、**同じケースの `task_id`** を再開して採点を依頼する。採点中は成果物を書き換えない。サブエージェントは期待結果の表の各行について、指定された確認先の文書箇所または対話を根拠に0点か1点で採点し、`score.md` に得点・合否・各行の根拠（ファイルの節・行または対話のターン）・0点の理由を保存して返す。全行を満たせば合格とし、指定された文字列以外は文面一致を求めない。未確認情報の確定事項への混入、または人間が確定した回答の未反映は得点に関係なく不合格とする。
6. 親は各ケースの `score.md` を確認し、ケース別の得点・合否・失敗箇所・根拠へのパスを `<実行ID>/report.md` と対話で報告する。生成・採点は同じケースのセッションで行うため、その採点は自己評価であることを明示する。Taskの実行用エージェントが利用できない、セッションを継続できない、または成果物が作れないケースは理由を添えて未実施とし、親による代行やCLI起動で合格扱いしない。

認証ファイルをコピー・リンクして実行環境の制約を回避しない。
