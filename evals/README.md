# 評価ケース

このリポジトリ内で Codex を使う場合は、`$test-extended-pencil` でケースの実行と採点を依頼できる。

`prompts/` の指示文と `expectations/` の期待結果は同じ番号・名前で対応する。テスト用スキルは `skills/test-extended-pencil/.work/` の下にケースごとの作業ディレクトリを作り、指示文ファイルの引用部分を対象エージェントへ渡す。複数ターンのケースは、記載順に同じ対話と同じ成果物で続ける。生成されたMarkdownとエージェントの質問を、対応する期待結果で採点する。

各評価項目は満たせば1点、満たさなければ0点。表現や見出しの細かな違いは失点にしない。確定していない内容が「確定事項」に入った場合、または人間の回答で確定した内容が反映されない場合は、そのケースを不合格とする。実行結果と失敗理由を記録し、修正前後で同じケースを比べる。

| ケース | 主な確認点 |
| --- | --- |
| 01 | 要件定義の初回作成と未決事項の質問 |
| 02 | 既存SQLから読み取った情報の扱い |
| 03 | 画面設計の状態と未決事項 |
| 04 | API契約にない情報を補わないこと |
| 05 | 回答後の確定・却下・新要件の反映 |
| 06 | 汎用文書と、未決事項がない場合の終了 |

評価ケースは正解の文面を固定するためのものではない。期待結果は、文書に含めるべき事実、混入してはいけない推測、対話上の振る舞いを示す。実際の利用で新しい失敗が出たら、その状況を再現する指示文を追加する。
