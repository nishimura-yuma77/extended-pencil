# test-extended-pencil

このリポジトリの `SKILL.md` を評価対象、`evals/` を評価セットとして扱う。設計文書を作る通常の依頼には使わない。

## 実行

1. リポジトリ直下の `SKILL.md`、`evals/README.md`、選択したケースの `evals/prompts/` を読む。ケース指定がなければ全件を対象とする。期待結果は成果物ができるまで読まない。
2. リポジトリ直下の `skills/test-extended-pencil/.work/` に、実行ごとに一意のディレクトリを作り、ケースごとに作業ディレクトリを分ける。指示文ファイルの引用部分をユーザーからの依頼として、このCodexプロセスで `extended-pencil` の指示に沿って処理する。指定された `docs/` などの出力先はケースの作業ディレクトリを基準にする。
3. 複数ターンのケースは同じ文書を順に更新する。各ターンの質問、初回と最終のMarkdown、実行時の問題をケースの作業ディレクトリへ保存する。評価対象の `SKILL.md`、テンプレート、評価ケースは変更しない。
4. 成果物を作ってから対応する `evals/expectations/` を読み、各チェック項目を成果物と対話を根拠に0点または1点で採点する。文面の一致は要求しない。未確認情報の確定事項への混入、または人間が確定した回答の未反映は、そのケースを不合格とする。
5. ケース別の得点、合否、失敗箇所と根拠となる文書の箇所・対話を報告する。同じCodexプロセスで生成と採点を行った結果は「スモーク確認」と明示し、独立した回帰テストとして扱わない。実行できないケースは未実施と記す。

ユーザーが独立した評価を求めた場合だけ、別のCodexセッションで同じケースを実行する。その際も生成物は `.work/` に置き、認証ファイルをコピー・リンクして実行環境の制約を回避しない。
